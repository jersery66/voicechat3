## 一、总体结论

项目架构思路清晰、工程化较好：双通道 `|||` 切分、反转容错、Agent 统一路由与字段兼容、标签解析的大小写/缺字段鲁棒性、ASR 纠错、线程安全主框架（队列 + 代际令牌）、资源释放兜底都落地得不错。

但存在一组**会实际影响产品行为的中高严重度缺陷**，集中在：
1. **状态一致性**：症状累计分只在一条路径重置、量表启动轮次门禁失效，可能产生"意外/连环触发量表"。
2. **输出纯洁性**：历史侧清洗与生成侧不一致、stop 列表被关掉、常用词"防御"误杀正常回复——直接体现在用户听到的内容。
3. **并发与资源生命周期**（TTS/视频/STT）：CosyVoice 半成品、视频/STT 流泄漏、TTS 无卸载保护。
4. **UI 线程安全与核心流程可用性**：模型判定结束时在错误线程弹模态框、换人流程缺方法崩溃、强制放松后会话卡死。
5. **安全**：受试者编号未净化导致路径穿越（唯一高危安全问题）。
6. **重构模块契约不一致**：`app/engine.py`/`adapters/` 与契约/生产接线存在缺口（目前靠影子模式掩盖）。

**严重程度分布（去重后）**：
- 🔴 高（High）：16 项
- 🟠 中（Medium）：29 项
- 🟢 低（Low）：20 项

## 二、🔴 高严重度问题（必须优先修）

### H1.【安全】路径穿越：受试者编号未净化即拼入路径
- **文件**：`data/data_manager.py:63`（`set_user_id`）、`:149`（`save_user_profile`）、`:355-361,393`（`start_new_session`）；`services/report_generator.py:156-158`
- **问题**：`set_user_id` 仅把 `None/空/空白` 映射为 `"default_subject"`，完全不净化 `/ \ .. :` 等字符。受试者编号是用户可输入字段，可写出/覆盖 `data_root` 之外的任意文件。
- **修复**：用白名单净化 `cleaned = re.sub(r'[^A-Za-z0-9_\-]', '_', (user_id or "").strip()) or "default_subject"`，并截断长度；`report_generator` 的 `subject_id` 同样净化后再拼文件名。

### H2.【UI/线程】模型判定结束时在工作线程弹模态对话框 → 崩溃
- **文件**：`ui/main_window.py:555` → `:1638` `_show_end_decision_dialog()` → `:1656` `dialog.exec()`
- **问题**：`_post_pipeline_routing` 运行在 `threading.Thread`，当 pipeline 返回 `end_type` 时直接调用结束请求并构造 `QDialog` 在子线程 `exec()`，触发 Qt 报错 *"Cannot create children for a parent that is in a different thread"*。
- **修复**：改为 `self.processing_queue.put(("end_session_request", et))`，在 `process_queue()` 的 GUI 线程分支处理（与 `:663` 的 `auto_end_session` 类似），所有 `dialog.exec()` 必须在 GUI 线程。

### H3.【UI】`ControlPanel` 无 `reset_form()` → 「修改信息/新会话」崩溃
- **文件**：`ui/main_window.py:933` `self.control_panel.reset_form()`；`ui/control_panel.py`（全文件无该方法）
- **问题**：`_prepare_next_subject()` 调用 `reset_form()`，而 `ControlPanel` 仅定义了 `reset_recording`，抛 `AttributeError`，会话结束/换人流程中断，下一位被试无法开始。
- **修复**：在 `ControlPanel` 实现 `reset_form()`（清空 `QLineEdit`/`QComboBox`、复位按钮与 label）；同时给 `_prepare_next_subject` 加 `try/except` 兜底。

### H4.【UI】「结束时强制放松」走完后会话永远无法结束
- **文件**：`ui/main_window.py:2037-2052`（`force_relaxation` 分支）与 `:1193-1200`（`_on_video_finished` 的 pending 检查）
- **问题**：用户手动结束且放松未完成时，进入 `force_relaxation` 分支设 `self._session_ending = False` 并返回，但 `_pending_end_after_video` **未设置**（它只在 `state == VIDEO_PLAYING` 时设置）。用户随后做完放松，`_on_video_finished` 检查 pending 为 `None`，只回到聊天，再也不会重新触发结束。这是可达主路径。
- **修复**：在 `force_relaxation` 分支保存待办结束：`self._pending_end_after_video = end_type`；`_on_video_finished` 据此重新调用 `_request_end_with_readiness_check(..., allow_force_relaxation=False)`。

### H5.【核心/状态】`symptom_scores` 仅在"症状累计触发"路径重置 → 量表完成后可能连环触发
- **文件**：`services/pipeline.py:904`（`start` 分支）、`:987-995`（确定性触发）、`:999-1037`（累计块，重置仅在 1032）
- **问题**：累计症状分 `self.symptom_scores` 只在"症状总分达阈值"路径重置。Agent 路由 `start` 或确定性兜底启动时**不重置**，量表完成后下一轮若残留分 ≥3 会立即再次触发另一量表。
- **修复**：在 agent `start` 分支与确定性触发成功启动量表时，同样执行 `self.symptom_scores = {"PHQ-9":0,"GAD-7":0,"PCL-5":0}; self.symptom_turns = 0`。

### H6.【核心/输出】`_history_visible_text()` 不处理反转、不剥离内部词 → 历史污染
- **文件**：`services/llm_service.py:246-249`（保存历史）、`:254-267`（`_history_visible_text`）
- **问题**：用 `text.rsplit("|||", 1)[-1]` 假设右=口语。但 `pipeline._stream_llm` 已专门处理"反转格式"，当模型反转输出时取到的是分析侧喂回下一轮；且未用 `_FORBIDDEN_INTERNAL_TERMS` 清洗，内部策略标签可能进入历史。
- **修复**：让 LLM 历史保存走与 `_stream_llm` 同源的"已纠正口语"，或在 `_history_visible_text` 内同步反转判定与 `_FORBIDDEN_INTERNAL_TERMS` 剥离。

### H7.【TTS】CosyVoice `generate_and_play` 缺 `_play_lock`
- **文件**：`tts_service_cosyvoice.py:206`；`__init__`（28-38 行）未创建锁
- **问题**：VoxCPM2 有播放锁，但 CosyVoice 既不在 `__init__` 创建锁也不加锁。一旦启用，并发调用会导致两个播放同时进行、声音错乱，且 `finally` 把共享 `is_playing=False` 打断另一个播放循环。
- **修复**：`__init__` 加 `self._play_lock = threading.Lock()`，在 `generate_and_play`/`play_audio` 入口 `with self._play_lock:` 包裹（同 voxcpm 写法）。

### H8.【TTS】CosyVoice 播放 worker 异常退出后生产者永久阻塞 → 线程挂死
- **文件**：`tts_service_cosyvoice.py:174-176`（worker 吃异常后 break）、`:259`（`playback_queue.put` 无超时）、`:263`（`join(timeout=10)`）
- **问题**：worker 抛出异常直接 `break`，不设停止信号；生产者无超时 `put` 会阻塞，`finally` 永远到不了，`is_playing` 维持 `True`，TTS 线程永久卡死。
- **修复**：worker 异常时 `stop_event.set()`；生产者 `put(chunk, timeout=1.0)`，队列满 `break`；循环检查 `stop_event`；`finally` 中 `stop_event.set() + join`。

### H9.【视频】视频播放未关闭 `VideoFileClip` 且 `finally` 调全局 `pygame.quit()`
- **文件**：`video_service.py:46`（`clip = VideoFileClip(...)`）、`:166-182`（`finally` 未 `clip.close()`）、`:175`（`pygame.quit()`）
- **问题**：每次播放泄漏 ffmpeg 子进程/文件句柄；`pygame.quit()` 是进程级销毁，与 `game_service` 共用 pygame，视频结束后可能破坏游戏所依赖的 pygame 状态。
- **修复**：`finally` 中显式 `clip_resized.close()`；不要无条件 `pygame.quit()`，或加引用计数/互斥；游戏与视频互斥管理 pygame 生命周期。

### H10.【STT】VAD 自动停止只置标志，未关闭录音流 → 麦克风流泄漏
- **文件**：`stt_service.py:177-178`、`:242-251`、`:261-268`
- **问题**：VAD 触发仅 `is_recording=False`，collect 线程退出但 `sd.InputStream` 仍运行，直到调用方显式 `stop_recording()`。若调用方未紧跟调用，麦克风持续打开。
- **修复**：抽取 `_stop_stream()` 私有方法，VAD 分支与 `stop_recording` 共用。

### H11.【TTS】两个 TTS 实现 `load_model` 无重复加载防护、无卸载/显存释放
- **文件**：`tts_service_voxcpm.py:67-116`、`tts_service_cosyvoice.py:51-96`、`cleanup`（voxcpm `:354-356`、cosyvoice `:355-360`）
- **问题**：重复调用会再次实例化占用 GPU 显存（无 `del`/`.cpu()`/`empty_cache()`）；`cleanup()` 不释放大模型权重。超大模型同机争抢 12GB+ 显存，易 OOM。
- **修复**：`load_model` 开头 `if self.model is not None: return True`；新增 `unload_model()`；`load_model` 的 try/except 回滚半成品资源。

### H12.【脚本】`download_media.py` 引用未定义的 `MUSIC_DIR` → Pixabay/Archive 下载必崩
- **文件**：`scripts/download_media.py:174`、`:232`
- **问题**：`output_dir = MUSIC_DIR / "pixabay"` / `"archive_org"` 引用了从未定义的 `MUSIC_DIR`，执行 `--pixabay`/`--archive`/`--all` 立刻 `NameError` 崩溃。
- **修复**：顶部补 `MUSIC_DIR = MEDIA_DIR / "music"`；两处改为 `MEDIA_DIR / "pixabay"` / `MEDIA_DIR / "archive_org"`。

### H13.【脚本】`preprocess_knowledge_base.py` 空文件触发 `IndexError` 且已就地覆盖（数据丢失）
- **文件**：`scripts/preprocess_knowledge_base.py:249,261,279`
- **问题**：处理完打印 `fixed[0]['keywords']`，若 `data == []` 抛 `IndexError` 崩溃，而前面文件已用 `open(path,'w')` 就地重写 → 原条目永久丢失，且无备份。
- **修复**：打印前判空 `if fixed: print(...)`；处理前备份原文件；单文件失败不影响其余。

### H14.【app 引擎】引擎只注册了 14 个命令中的 6 个，其余静默丢弃
- **文件**：`app/engine.py:85-92` vs `app/contracts.py:159-174`
- **问题**：`ExitCommand`/`PlayGameCommand`/`SelectMediaCommand`/`ConfirmUserInfoCommand`/`PrepareNextSubjectCommand` 等 8 类无处理器，`process_command` 只 `logger.warning` 后 `return`。
- **修复**：为每个命令补处理器或显式拒绝；未实现命令在 `process_command` 显式报错而非静默吞。

### H15.【app 引擎】契约定义的 `SessionEndedEvent` 从未被发出
- **文件**：`app/engine.py:331-335` vs `app/contracts.py:245-261`

- **修复**：在 `mark_session_ended()` 补 `self._emit(SessionEndedEvent(...))`；或在权威化前明确职责归属。

### H16.【app 适配器】`assess_crisis_risk` 协议签名与实现不一致，且 conformance 测试查不出

## 三、🟠 中严重度问题（应修）

### 核心对话管线 / LLM
- **M1. Agent 的 `exit_intent`/`recommend_media` 合法 action 未被 pipeline 消费**（`agent_service.py:794-797`；`pipeline.py` 全文未读）。用户表达退出时 pipeline 完全忽略。→ 在路由处理块增加 `exit_intent` 判断。
- **M2. `_call_json` 硬编码 `response_format={"type":"json_object"}`**，与 `route_conversation_actions` 刻意避开它的理由自相矛盾；若 Ollama 小模型不支持，除路由外所有 Agent 调用都会降级兜底。→ 与路由保持一致，去掉 `response_format`，靠 `_parse_json_loose` 兜底。
- **M3. `score_symptom_signals` 把"没有/不知道"当症状信号累加**（`core/scoring.py:164-170`）。"没有"是否认非症状，连否几次可把 PHQ 推到阈值触发量表。→ 从 evasive 移除"没有/不知道"或单独计数。
- **M4. `infer_scale_score_from_text` 仅 PHQ-9 做 item-aware**，GAD-7/PCL-5 频率词无条件计分（`core/scoring.py:57-88`）。→ 为 GAD-7/PCL-5 实现 per-item 症状词匹配。
- **M5. 跨题评分用错题号**（`pipeline.py:1222-1232`）：`detected_item` 识别出实际题号，但调用 `infer_scale_score_from_text` 仍传当前题号 `self._active_scale_q`。→ 改为传 `detected_item`。
- **M6. Agent 返回的 `scale` 未做合法性/归一化校验**（`pipeline.py:906-907`；`agent_service.py:785`）。若返回 `"PHQ9"`/`"phq-9"`，`SCALES.get` 返回 None，量表既无法推进又占用不会命中的名字。→ 白名单归一化，非法值降级回退。
- **M7. 停止序列（stop）被注释掉，未下发 Ollama**（`llm_service.py:120-125`）。约束明确要求仅用该 stop 列表，注释后模型可能编造用户轮次。→ 取消注释恢复 stop。
- **M8. `_FORBIDDEN_INTERNAL_TERMS` 含过宽"防御"**（`core/tags.py:77-85,108-109`）。"防御"是日常常用词，模型偶然输出含"防御"的正常句会被整段丢弃或子串删残。→ 移除"防御"，只用"高/中/低防御"等歧义短语。
- **M9. `MIN_ROUNDS_BEFORE_SCALE` 导入却从未使用**（`pipeline.py:12` vs 执行流）。量表启动轮次门禁失效，Agent 第 1 轮即可启动量表。→ 在 `start` 分支加 `and current_rounds >= MIN_ROUNDS_BEFORE_SCALE` 守卫。

### 状态机 / 报告 / 数据
- **M10. FSM「强制放松」判定看不到 pipeline 的 `relaxation_used`**（`core/session_fsm.py:106-119`）：已推荐过放松但用户跳过时，结束时仍会再次强制推荐，与"每会话仅一次"冲突。→ 把 `relaxation_used` 作为入参加入判定。
- **M11. FSM 缺 `VIDEO_PLAYING → SESSION_ENDING` 转移**（`core/session_fsm.py:63-67`）：放松中请求结束会被 `transition_to` 拒绝，状态机卡死。目前靠 main_window 延迟结束规避，但 FSM 对中断不健壮。→ 给 `VIDEO_PLAYING` 增加 `SESSION_ENDING`。
- **M12. `MAX_CONVERSATION_MINUTES` 非"硬上限"**（`report_service.py:184-221`；`pipeline.py:1336-1337`；`main_window.py:1262-1296`）：到达上限仅软性询问一次，用户点继续后 `continued_after_time_limit=True`，会话可无限延长。→ 落实二次硬截止或改文档措辞。
- **M13. `parse_scale_tags` 不校验分数上下界**（`core/tags.py:45-53`）：LLM 输出 `S9`/`S5` 越界分原样累加。→ 引入 `SCALE_ITEM_MAX` 表 clamp 或 warning。
- **M14. `scale_fsm.py` 名不副实**：仅数据容器，约束 #6 要求的进入/退出/跳项/完成逻辑 100% 在 `pipeline.py`。→ 把转移方法迁入本文件加不变量断言，或文档明确"pipeline 为权威"。
- **M15. `end_guard` 非线程安全**（`core/end_guard.py:27-36`）：`begin()` 先判断再置位非原子，且 `defer_for_relaxation()` 无条件清 `_ending`。→ 用 `threading.Lock` 包裹判断+置位。

### STT/TTS/视频/情绪
- **M16. VoxCPM2 播放缓冲区线性非环形且硬上限 120s**（`tts_service_voxcpm.py:184,251-272`）：超长音频 `buf[...]=...` 切片长度不符抛 `ValueError`。→ 改环形缓冲或写入前边界守卫。
- **M17. VoxCPM2 `play_audio` 用 `sd.play(blocking=True)` 持锁阻塞调用线程**（`tts_service_voxcpm.py:327-346`）：在 UI 线程调用会冻结界面。→ 改为非阻塞或约束只在工作线程调用。
- **M18. 视频无外部停止/中止机制**（`video_service.py:20-184`）：会话结束无法中断全屏视频。→ 增加 `self._abort = threading.Event()`，编排器切出 `VIDEO_PLAYING` 时 `player.stop()`。
- **M19. CosyVoice `cleanup()` 关闭恒为 None 的 `self.stream`**（`tts_service_cosyvoice.py:355-360`）：实际关不掉活动流，`pyaudio.terminate()` 在流仍开时调用可能异常。→ 维护活动流引用。
- **M20. `emotion_tracker` 非线程安全**（`emotion_tracker.py:25-39`）：管线写、UI 读跨线程无锁，`_negative_streak` read-modify-write 非原子。→ 用 `Lock` 保护写入与复合读取。
- **M21. `report_tool._score_scales` 用位置而非真实题号映射**（`tools/report_tool.py:149`）：`answers` 非升序或缺题会错位。→ 按真实题号排序取值或调 `mgr.score_scale`。
- **M22. `error_monitor` 单例竞态**（`error_monitor.py:89-99`）：并发首次调用可能重复挂载 handler 写盘。→ `Lock` 保护单例创建。

### UI 层
- **M23. 多处跨线程共享标志无同步**（`main_window.py:419,542,846,2014-2015,1996`）：`_pipeline_busy`/`_session_ending`/orchestrator 状态由工作线程写、GUI 线程读。→ 统一收口到 GUI 线程（队列/信号）。
- **M24. `SessionEndDialog` 路径完全孤立（死代码）**（`main_window.py:627-630,1002-1011`；`dialogs.py:34-125`）：正常结束流程从不 `put(("session_end",...))`，运营者看不到反馈文本/放松建议/报告路径。→ 接入展示或删除死代码。
